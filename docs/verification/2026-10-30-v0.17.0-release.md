# T-Cube 0.17.0 release verification

Release source/tag target: `e84c813be5f156f3bfd34b394200fa6dee4b2fe1`.
Release: https://github.com/gd0306/t-cube/releases/tag/v0.17.0

## Delivered behavior

Both clients support apps, folders, individual files, HTTP(S) websites and six curated system-settings pages. Default file/browser handlers are used. URL targets use bundled icons and skip filesystem checks. Old app/folder configuration and backups decode; website protocols, credentials and settings destinations are validated at input and launch. The release also includes explicitly enabled common-content templates.

## Verification

- macOS: 88 native Swift Testing and 106 core tests passed with `swift test --parallel --num-workers 1 --scratch-path .build/tests`.
- Two additional synchronous XCTest cases passed: each ran the real native type-picker → website/settings form → Cancel chain five times. They check both website inputs, all six curated settings options, unchanged configuration and no persisted file.
- Windows: local Node 22 typecheck/build and tests (155 passed, one Windows-only skip) passed. [Source installation CI](https://github.com/gd0306/t-cube/actions/runs/40920148772) passed on Windows 2022 and 2025, including all 156 tests and the installed-runtime smoke suite.
- [Windows installer CI](https://github.com/gd0306/t-cube/actions/runs/40920177561) built and verified the real per-user NSIS installer. Downloaded SOURCE_COMMIT matches the release tag target. Diagnostics confirm website add/replace across all four slots, credential/unsafe URI rejection, settings selection, offline icons and focus-checked native template paste into an owned receiver.
- `bash scripts/build-app.sh`, `bash scripts/build-dmg.sh --skip-build`, and `bash scripts/verify-dmg.sh` passed. The mounted DMG app, executable, ad-hoc signature, Applications link and installation note were verified.
- Installed 0.17.0 at `/Applications/T-Cube.app`, retained the previous app under `build/install-backups/0.17.0/`, verified executable hash/signature and running path. Native editor shows new target kinds. Existing slot sequence and content-library data retained; configuration was re-encoded by the app during save/restore of an unchanged slot order. The GUI test did not add fixture entries to the user's library.
- A pre-existing mounted old DMG contained another identically named app, which UI discovery inadvertently launched. It was exited and the old image ejected. Verification subsequently used the installed path explicitly; the running new model retained the current configuration, including the fields the older client did not encode.
- Independent code review completed; URL canonicalization and typed repair findings were fixed with regressions. `git diff --check` passed.

The earlier Windows run failed only its hardcoded old-version assertion, now replaced by package-metadata comparison; the earlier installer dispatch used a short ref, now replaced by the full source SHA. Native macOS external browser/settings launching was verified through captured handlers and native URI availability, rather than opening all external pages manually. Windows native checks ran on hosted runners, not a physical Windows PC.
