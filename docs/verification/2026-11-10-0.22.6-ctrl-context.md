# 0.22.6 Ctrl 操作仲裁与一秒唤起

## 行为与根因

原实现让悬停还原尺寸与剪贴板长按独立响应同一 Ctrl，缺少按压归属。`0.22.6` 保留一秒唤起，并将整次按压分配给一个操作：

- 鼠标在可见立方体内，或立方体正在交互／拖动时，Ctrl 优先用于还原尺寸与拖动；本轮不打开剪贴板。
- 鼠标在立方体外，单独长按 Ctrl 一秒打开历史。其它按键、鼠标按钮或滚轮仍取消。
- 按住时移入立方体，会锁定取消剪贴板，缩小或再次移出也不会重新计时；必须松开后重新在外长按。
- 保留启动已按住、睡眠／会话切换、采样中断保护，以及透明玻璃、默认记录、文字编辑和登录项选择。

macOS 的窗口移动／修饰键事件会锁定按压归属，剪贴板每次采样（包括释放）都会重验。首次携带 Ctrl 的事件已在窗口外时，在更新悬停几何前保留上次窗口内状态；不在释放后的仲裁查询中重复使用旧悬停。Windows 在 Raw Input 按下、Ctrl 期间鼠标包及 tick 中判断归属，使用长按状态机锁定取消。

## 开发验证

- macOS 冲突回归先红后绿：原 4 例 9 个问题，新增快速退出时序确认旧路径于 1 秒误弹。修复保留释放后重新按压的断言，不放宽取消或触发边界。
- 最终聚焦：40 项原生测试及 8 项核心测试通过，包括 6 项冲突用例、悬停几何、延迟进入、按压截止时间、释放／系统重置和快捷面板。
- Windows 全套 282 项：279 通过、3 项需 Windows 的测试跳过；类型检查、构建通过。新增实际 Host + 长按状态机回归覆盖还原后移出、按住中途进入、快速首次采样及释放后重新在外按住。
- Windows 原生烟测新增真实指针进入／退出、Ctrl 还原持续超过 1 秒不弹历史，再释放后在外长按；可见窗口的预算为 1000–1250 ms。此部分需以 Windows CI 的实际结果验收，不能以本机单元测试替代。
- macOS 既有完整同进程动画顺序失败边界保留，见[此前发布记录](2026-11-08-release-consistency.md)。不将分组通过改称未拆分完整套件绿色。
